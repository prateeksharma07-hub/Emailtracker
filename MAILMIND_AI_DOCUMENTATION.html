1 Executive Overview & Problem Statement

Modern professionals face relentless email overload. The average enterprise user receives over 120 messages daily, spending upwards of 2.5 hours triaging inbox notifications, replying to meeting requests, extracting deadlines, and sifting through spam and marketing newsletters.

The Problems with Traditional Email

  • No Contextual Prioritization: Important vendor audits get buried beneath newsletters.
  • Missed Action Items: Deadlines hidden in long body paragraphs are forgotten.
  • Privacy Leaks in AI Tools: Most existing AI email plugins transmit raw credentials, bank OTPs, and confidential identity data to third-party LLM cloud servers.
  • Accidental Automation Dispatches: Dangerous auto-send bots that send hallucinations directly to clients.

The MailMind AI Solution

  • Autonomous Multi-Class Triage: Messages categorized into Urgent, Work, Meeting, Task, Personal, Newsletter.
  • Zero-Leak Regex Guard: Sensitive OTPs, passwords, and banking codes are scrubbed locally before AI processing.
  • Strict Human-in-the-Loop Gate: AI only writes drafts. No email can EVER leave the system without explicit user review.
  • Local Data Sovereignty: Tokens and metadata stay in a private local SQLite database on the user's machine.
🛡️ Absolute Privacy Guarantee
MailMind AI requests the strict minimum permissions from Google Cloud: gmail.readonly (read messages) and gmail.compose (create drafts). The dangerous gmail.send scope is permanently disallowed. Furthermore, zero automatic deletion or forwarding is permitted.

3 Feature Deep-Dive: How Each Component Works

3.1 Smart Inbox & Automated AI Triage

When emails arrive from Gmail API or are synchronized, the system triggers the Email Ingestion & Triage Pipeline:

  1. MIME Tree Parsing: Gmail messages arrive as complex multi-part MIME payloads. gmailService.js traverses all nested parts, extracts both formatted HTML and plain text, cleans snippet previews, and standardizes sender headers (e.g., "Prateek Sharma <prateek@example.com>").
  2. Privacy Guard Check: Before sending content to Gemini, the email is analyzed by sanitizationService.js. If an OTP, banking number, password link, or credit card is detected, the message is flagged as is_sensitive = 1 and bypasses external AI entirely. A local safe template summary is generated instead.
  3. Gemini Multi-Classification Prompt: Clean emails are submitted inside <untrusted_email_content> isolation tags to Gemini 3.5 Flash with strict JSON schema outputs.

3.2 Action Items & Deadlines Extraction

Rather than forcing the user to reread dense email threads, MailMind AI's NLP engine extracts actionable commitments into the tasks table:

  • Task Title Extraction: Concise imperative phrases (e.g., "Review Phase 2 setup for AI Email Assistant", "Suggest a suitable date and time for project review").
  • Deadline Detection: Extracts relative and absolute due dates (e.g., "by Thursday 5 PM", "within 48 hours", "Nov 20, 2026").
  • Interactive Completion: Users can check off tasks right from the dedicated Tasks view or from inside the email detail view, synchronizing directly with the local database.

3.3 AI Reply Studio & Human-in-the-Loop Approval

For every non-sensitive email, MailMind AI automatically generates 3 contextual reply drafts:

👔 Professional

Formal, polite, structured with greeting and standard enterprise sign-off.

⚡ Concise

Direct, high-efficiency, 2-line acknowledgment ideal for busy executives.

📋 Detailed

Thorough, addressing all points raised in the original thread item by item.

⚠️ The Human Approval Gate
Clicking "Send Draft" does NOT dispatch the email directly. Instead, it opens the Human Approval Modal. The user can review the recipient, subject, and body, adjust the tone, edit any sentence, and MUST check the authorization box "I confirm human review and authorize creating this draft" before any API call is permitted.

4 Google OAuth 2.0 & Security Architecture

MailMind AI adheres to production-grade security standards to ensure absolute safety for user credentials and correspondence:

1. Cryptographic CSRF State Defense

Every authorization session generates a 64-character cryptographically secure hex state token stored in SQLite with a 15-minute expiration time. When Google redirects back to /api/auth/callback: 

// Single-use burn pattern prevents replay & CSRF attacks:
const record = db.prepare('SELECT state, created_at FROM oauth_states WHERE state = ?').get(state);
if (!record || Date.now() - record.created_at > 15 * 60 * 1000) {
  throw new Error('CSRF validation failed: Invalid or expired OAuth state parameter.');
}
db.prepare('DELETE FROM oauth_states WHERE state = ?').run(state); // Consumed immediately

2. Zero Token Exposure to Frontend

OAuth access tokens and refresh tokens are stored exclusively in the backend SQLite accounts table. API endpoints such as /api/auth/status and /api/emails sanitize their output using projection stripping: 

// Frontend receives metadata only — TOKENS ARE NEVER TRANSMITTED:
return {
  id: row.id,
  email: row.email,
  name: row.name,
  picture: row.picture,
  last_synced_at: row.last_synced_at,
  is_demo: isDemo
  // access_token: UNDEFINED
  // refresh_token: UNDEFINED
};

3. Zero-Leak Sensitive Content Sanitization

Emails containing verification codes or financial records are quarantined before AI ingestion: 

const SENSITIVE_PATTERNS = [
  { type: 'OTP', regex: /\b(?:otp|one-time password|verification code|security code)\b.{0,30}\b\d{4,8}\b/i },
  { type: 'CREDIT_CARD', regex: /\b(?:\d{4}[ -]?){3}\d{4}\b/ },
  { type: 'BANKING', regex: /\b(?:account number|ifsc|routing number|swift code|iban)\b/i },
  { type: 'PASSWORD', regex: /\b(?:temporary password|reset your password|password reset link)\b/i }
];
